# QLD 전략 연구 프로토콜 v2

한 번의 요청 = 한 스텝. **넓게 찾고 좁게 검증하는 깔때기**다. 계산이 필요한 일(후보 생성·채점·공격·판정 숫자)은 코드가 하고, LLM은 코드가 못 하는 일(새 아이디어, 경제적 해석, 코드 검토, 최종 판단)만 한다.

v1(S08)에서 바꾼 이유: 사람 손으로 만든 후보 12개로는 탐색이 좁았고, LLM 다섯 역할 중 넷이 검증만 하면서 같은 문서를 각자 읽어 토큰 약 90만 개를 썼다. v2는 코드 스크린으로 수백 개를 보고, LLM은 셋(전략가·비평가·결재자)만 짧은 자료로 일한다.

## 깔때기

| 단계 | 누가 | 하는 일 | 산출물 |
|---|---|---|---|
| 0 계획 | 진행자(메인 세션) | 목표를 정한다. 사용자가 아이디어를 주지 않으면 `IDEAS.md`의 빈칸과 챔피언 약점에서 기대값이 큰 곳을 고른다. `node lib/brief.js --step Sxx --goal "..."` | `BRIEF.md`, 스텝 문서 머리말 |
| 1 넓은 스크린 | 코드 | `node lib/screen.js --step Sxx` (카탈로그 62개 지표 × 훅 3 × 문턱 3 + 구조 변형, 약 5분). 필요하면 `--pairs`로 상위 지표 두 개 조합 | `steps/Sxx-screen.jsonl`, 요약표 |
| 2 전략가 | LLM 1명 | `BRIEF.md`와 스크린 요약만 읽는다. ① 카탈로그 밖 새 아이디어 5개 이상(행동 유형이 서로 다르게)을 사전 등록하고 모듈로 만든다 ② 새 지표는 `catalog.js`에 추가해 이후 스크린에 영구 편입 ③ `--extra`로 함께 채점 ④ 결선 후보 최대 3개를 고른다 | 결선 후보 설정, 사전 등록 |
| 3 배터리 | 코드 | 결선 후보마다 `node lib/battery.js` (이웃값·비용 2배·7월 시작·1억 거치·플라시보·연도별 기여·결정적 매매·문턱 여유·자동 판정, 후보당 약 30초) | `steps/Sxx-battery.md` |
| 4 비평가 | LLM 1명 | 배터리 결과와 결선 모듈 코드만 읽는다. 미래 정보 누수(A8), 파라미터 수와 근거(A6), 개선이 한 사건에서만 나오는지, 사용자가 지킬 수 있는지를 판단한다. 숫자를 다시 돌리지 않는다(필요하면 최대 2회) | 비평 메모 1쪽 |
| 5 결재 | LLM 1명 (독립) | 자동 판정표 + 비평 메모 + 전략가 근거(합쳐 3쪽 이내)만 읽고 채택·보류·기각 | 결재표 |
| 6 기록·보고 | 진행자 | 스텝 문서, `LEDGER.md`, `IDEAS.md` 갱신, 커밋. 사용자 보고 | |

분석가를 기술·매크로로 나누지 않는다. 신호 출처보다 **행동 유형**(이탈·복귀·노출 크기·레버리지·적립금·규칙 분산·세금·달력)이 결과를 가르기 때문에, 전략가는 행동 유형을 넓게 퍼뜨려 후보를 낸다.

## 검증 세트 (스텝 사이에 바꾸지 않는다)

- 주 70만원 적립(배터리는 1억 거치도 함께), 세후 원화, 매일 종가 신호 → 다음 거래일 종가 실행.
- **발견 세트**: 나스닥100 10년(1999~2016 시작), 나스닥100 5년. **확인 세트**: 나스닥100 10년 1986~1998 시작, S&P 2배 10년·5년.
- 스크린 점수 = min(발견 세트 평균, 확인 세트 평균) of (챔피언 대비 Δ중앙 + 0.5·Δ최악, %p) − 사례가 5%p 넘게 나빠지면 벌점. 두 세트 모두에서 좋아야 점수가 오른다.
- 사례 구간: 2025, 2022, 2020, 2018, 2008, 2000.
- 기준선(단순 적립·챔피언)은 `.cache/`에 저장돼 후보 하나는 시뮬레이션 한 번(1~2초)이다. 데이터·엔진·챔피언이 바뀌면 캐시는 자동으로 새로 만든다.

## 채택 기준표 (모두 통과해야 채택; A1~A5·A7·A10은 `battery.js`가 자동 판정)

| # | 기준 |
|---|---|
| A1 | 표본 밖 세트(N10oos, S10, S5) 어느 것도 챔피언보다 IRR 중앙값이 1.0%p 넘게 나쁘지 않고, 최악 IRR이 2%p 넘게 나쁘지 않다 |
| A2 | 개선: N10·N10oos·N5 중 최악 IRR이 2%p 이상 좋아지거나, N10과 N10oos의 IRR 중앙값이 둘 다 1%p 이상 좋아진다 |
| A3 | 사례 6개 중 챔피언보다 5%p 넘게 나쁜 구간이 없고, 4개 이상은 나쁘지 않다 |
| A4 | 새 파라미터를 각각 ±20%(또는 바로 옆 값)로 바꿔도 A1·A3을 유지하고 점수가 양수다 (봉우리가 아니라 고원) |
| A5 | 비용 2배와 7월 시작 구간에서도 점수가 양수다 |
| A6 | 스텝당 새 자유 파라미터 2개 이하, 근거는 시험 전에 기록, 임계값은 반올림한 값 (비평가 확인) |
| A7 | 1999년 이후 이탈 40회 이하 |
| A8 | 미래 정보 없음: 신호는 j일 종가까지, 지표별 발표 시차, 실행은 j+1일 (비평가가 코드로 확인) |
| A9 | 다중검정: 스텝 시도가 30회를 넘으면 A2의 개선 폭을 두 배(4%p / 2%p)로 올린다. 스크린은 넓게 하되, 이 기준과 A10이 그 대가를 치른다 |
| A10 | 플라시보: 같은 신호를 시간축으로 무작위 이동한 20개보다 점수가 높은 비율이 95% 이상 |

보조 경고(채택을 막지는 않지만 비평가가 판단): 연도별 기여에서 한 해가 60% 이상을 차지, 결정적 매매 직전 신호의 문턱 여유가 0.05 미만, 최장 시장 밖 기간이 챔피언보다 크게 김.

보류는 A2를 통과했지만 A4·A5 중 하나가 애매할 때만 쓴다. 보류 안은 같은 데이터로 다시 고르지 않는다.

## 검증 범위 (사용자 결정, 2026-10-18)

- 검증은 나스닥100과 S&P 2배까지만 한다. 해외 지수 스트레스 테스트는 판정에 쓰지 않는다(`lib/intl.js`, 배터리 `--intl`은 참고용으로만 남김).

## S09에서 추가한 규칙

- 진행자가 돌리는 격자(행동 파라미터 등)도 실행 전에 스텝 문서에 값을 적고 커밋한다(사전 등록 기록).
- 엔진에 없는 행동이 목표면 진행자가 스텝 시작 때 기본값이면 챔피언과 동일한 파라미터로 먼저 추가하고, 670개 구간 차이 0을 확인한다.
- 확인 세트(S&P)에서 규칙이 한 번도 발동하지 않으면 A1은 "확인 불가"이며 채택할 수 없다(보류까지만). 해외 지수 등 독립 약세장 데이터로 재현해야 한다.
- 비평가·결재자에게는 파일 경로가 아니라 자료를 프롬프트에 직접 붙여 넣는다(도구 호출 1회 이내). 에이전트는 한 번 호출될 때마다 기본 문맥 약 1.5~2만 토큰이 다시 든다.

## 토큰 규칙

- 에이전트는 `BRIEF.md`(약 2천 토큰)와 자기 단계 산출물만 읽는다. `engine.js`, 지난 스텝 문서 전체를 읽지 않는다.
- 점수표는 `--brief` 한 줄 형식으로 본다. 전체 표가 필요하면 결선 후보만.
- 에이전트를 재개(SendMessage)해서 토론시키지 않는다. 재개하면 이전 대화 전체가 다시 읽힌다. 토론은 산출물 파일을 다음 역할이 읽는 방식으로 한다.
- 연구 스텝은 새 세션에서 돌리는 것이 가장 싸다. 긴 대화의 문맥이 매 턴 다시 읽히기 때문이다.

## 과최적화를 피하는 습관

- 좋은 숫자 하나보다 이웃 값들이 고르게 좋은지를 본다. 플라시보보다 확실히 나아야 한다.
- 개선이 2000년이나 2008년, 1987년 한 구간에서만 나오면 의심한다(배터리의 연도별 기여).
- 규칙을 더하는 대신 빼서 같은 성과가 나오면 빼는 쪽을 채택한다.
- 채택된 챔피언은 채택일 이후 실제 데이터(매일 `data/status.json`)로 계속 추적한다. 이것이 유일한 진짜 표본 밖이다.
