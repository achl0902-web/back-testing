# QLD 전략 연구 프로토콜 v3

한 번의 요청 = 한 스텝 = **서로 다른 전략 방향 3개 이상**을 동시에 시험한다. 계산·기록·커밋은 `lib/step.js`가 하고, LLM은 아이디어(전략가)와 숫자 기준을 통과한 후보의 판단(비평가·결재자)만 한다.

v3로 바꾼 이유 (S11 피드백, 2026-10-18):
- S11은 방향 1개에 약 44만 토큰을 썼다. 진행자가 엔진을 고치고 격자를 짜고 문서를 손으로 썼고(메인 세션 도구 호출 약 40회), 범용 에이전트 3명(각 7만 안팎)이 모두 돌았다. 결과는 진행자 스크린에서 이미 전부 크게 음수였다.
- 스텝당 방향 1개는 느리다. 대부분 스텝이 기각이므로, 한 번에 여러 방향을 넓게 보고 숫자로 걸러지지 않은 것만 따진다.

## 흐름

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 0 준비 | 코드 | `node lib/step.js prep`: pull, 데이터 새로고침 시도, 다음 스텝 번호, 카탈로그가 바뀌었거나 데이터가 90일 넘게 새로워졌을 때만 넓은 스크린(약 5분), BRIEF 갱신 |
| 1 전략가 | LLM 1명 (`qld-strategist`) | BRIEF만 읽고(IDEAS 행동 유형표는 BRIEF에 포함) 방향 3~4개를 `steps/Sxx-plan.json`에 등록, 모듈 작성, `step.js check`로 오류·신호 발동률만 확인. **점수를 보지 않는다** |
| 2 실행 | 코드 | `node lib/step.js run Sxx`: 계획·모듈을 먼저 커밋(사전 등록) → 전 설정 스크린 → 방향별 최고 설정에 배터리 → `steps/Sxx.md` 작성 → 게이트 |
| 3 검토 | 조건부 | 게이트가 "검토 필요"일 때만 비평가(`qld-critic`) → 결재자(`qld-judge`). "자동 기각"이면 생략 |
| 4 마감 | 코드 | `node lib/step.js close Sxx --verdict … --why … [--ideas …]`: 스텝 문서 결론, LEDGER, IDEAS, BRIEF, 커밋·푸시 |

게이트: 방향의 최고 설정이 배터리 숫자 기준(A1~A5·A7·A10)을 모두 통과하거나 보류 조건(아래)에 들면 "검토 필요". 아니면 자동 기각이며, 판정 이유는 숫자가 대신한다.

## 전략가 규칙 (질을 높이기 위한 것)

- 방향은 3~4개, 행동 유형(이탈·복귀·노출 크기·레버리지·적립금·규칙 분산·세금·달력·신호 출처)이 서로 달라야 한다.
- 방향마다 적는다: **메커니즘**(왜 돈이 되는가), **겨냥한 약점**(BRIEF의 사례·세트·알려진 약점 중 무엇), **반증 예측**(맞다면 어느 세트·사례가 좋아지고 어디는 그대로여야 하는가).
- 구성: 최소 1개는 IDEAS 빈칸, 최소 1개는 챔피언 약점을 직접 겨냥. 지난 스텝에서 기각된 것의 변형은 최대 1개이고 새 근거가 있어야 한다.
- 방향당 자유 파라미터 2개 이하, 값 3개 이하(설정 최대 9개), 반올림한 값. 이산 파라미터(이평선 일수 등)는 `neighbors`에 이웃값을 직접 적는다.
- 엔진 수정이 필요한 방향은 넣지 않는다. 훅으로 안 되면 반환에 "엔진 필요"로 적고, 사용자 승인 아래 별도 도구 스텝으로 한다(진행자는 연구 스텝 중에 엔진을 고치지 않는다).
- 점수를 보고 고치지 않는다. `check`는 오류와 발동률만 보여 준다. 채점은 `run`이 한 번에 한다.

## v3.1 정비 (T02, 2026-10-19, S14 후)

- **A10 플라시보, 챔피언 대체형(rule "sig")까지 확장**: `S09_lib.run` 기반 후보는 챔피언 상태기계를 그대로 두고 후보의 훅(exitVotes·exitVeto·extraExit·enterOk·axes 차이·timeout)만 무작위 일수만큼 이동해 20회 채점한다. S09_lib를 쓰지 않는 sig 후보는 A10 "해당 없음"(채택 불가, 보류까지만).
- **상위 2개 연도 제외 합계**: 배터리가 이득이 가장 큰 두 해를 뺀 챔피언 대비 합계를 출력한다. 음수면 비평가가 "한두 해 의존"으로 다룬다(보조 경고).
- **사전 등록 감사**: 첫 `check`가 `steps/Sxx-plan.check1.json` 스냅샷을 남기고, `run`이 그 뒤 바뀐 값을 스텝 문서와 요약에 표시한다. 값 변경은 오류나 발동률 0%·100%일 때만 허용하고, 사유를 plan `changes`에 적는다.
- **run 자동 커밋**: run이 끝나면 결과물을 커밋·푸시한다. 검토 중에도 작업 트리가 깨끗하다.
- 검증: S14 B를 새 플라시보로 다시 돌림(T02, 도구 검증, 재선정 아님). 플라시보 100%(무작위 창 20개 최대 0.04), 1998·2016 제외 합계 −10.5%p → 비평가 조건 (3) 미달로 기각 유지.

## 검증 세트 (스텝 사이에 바꾸지 않는다)

- 주 70만원 적립(배터리는 1억 거치도 함께), 세후 원화, 매일 종가 신호 → 다음 거래일 종가 실행.
- **발견 세트**: 나스닥100 10년(1999~2016 시작), 나스닥100 5년. **확인 세트**: 나스닥100 10년 1986~1998 시작, S&P 2배 10년·5년.
- 스크린 점수 = min(발견 세트 평균, 확인 세트 평균) of (챔피언 대비 Δ중앙 + 0.5·Δ최악, %p) − 사례 5%p 초과 악화 벌점.
- 사례 구간: 2025, 2022, 2020, 2018, 2008, 2000.
- 검증 범위(사용자 결정 2026-10-18): 나스닥100과 S&P 2배까지만. 해외 지수(`lib/intl.js`, 배터리 `--intl`)는 판정에 쓰지 않는다.

## 토큰 규칙

- 연구 스텝은 저장소 루트에서 새 세션으로 시작한다. 그래야 경량 에이전트(`qld-strategist`·`qld-critic`·`qld-judge`)가 로드된다. 범용 에이전트는 도구 정의만으로 호출당 약 5만 토큰이 든다.
- 진행자는 BRIEF·IDEAS·PROTOCOL·엔진·스텝 문서를 읽지 않는다. 스킬에 명령이 다 있고, 스크립트 출력(각 20줄 이내)만 본다. 작업 목록 위젯과 중간 메시지는 쓰지 않는다(시작 한 줄 + 최종 보고).
- 비평가는 필요한 파일을 직접 읽는다(진행자가 붙여 넣으면 메인 문맥이 커져 매 턴 다시 읽힌다). 결재자는 도구 없이 진행자가 붙인 요약(게이트 출력 + 비평 메모)만 본다.
- 에이전트를 재개(SendMessage)해 토론시키지 않는다.
- 파라미터는 반드시 `params` 안에 넣는다. `score.js`는 모르는 최상위 키를 거부한다(S11).
- 목표: 자동 기각 스텝 약 15만, 검토 스텝 약 22만 토큰.

## 과최적화를 피하는 습관

- 좋은 숫자 하나보다 이웃 값들이 고르게 좋은지를 본다. 플라시보보다 확실히 나아야 한다.
- 개선이 2000년이나 2008년, 1987년 한 구간에서만 나오면 의심한다(배터리의 연도별 기여).
- 규칙을 더하는 대신 빼서 같은 성과가 나오면 빼는 쪽을 채택한다.
- 결과가 좋아도 근거 없는 파라미터를 미세 조정한 것이면 기각한다. "효과 없음"도 좋은 결론이다.
- 채택된 챔피언은 채택일 이후 실제 데이터(매일 `data/status.json`)로 계속 추적한다. 이것이 유일한 진짜 표본 밖이다.
- 채택 시 페이지와 매일 알림은 사용자 승인 뒤에만 바꾼다.

## 보고 형식 (사용자에게, 한국어, 휴대폰에서 읽기 좋게)

1. 결론 한 줄(방향별 채택·보류·기각)

3. 검토가 있었으면 비평 요지와 반대 의견
4. 과최적화 점검 요약(게이트 줄에서)
5. 다음 스텝 후보 2~3개, 채택이면 페이지 반영 여부 질문
