# QLD 전략 연구 프로토콜

> 누가 읽나: 사람, 비평가. 채택 기준표·보조 경고·과최적화 습관은 `node lib/step.js criteria`가 이 파일에서 뽑아 결재자에게 주고, `lib/brief.js`가 BRIEF에 싣는다(사본을 따로 두지 않는다).
> 무엇을 하나: 연구 스텝의 흐름, 검증 세트, 채택 기준, 운영 규칙을 정한다. 역할별 작업 지시는 각자의 파일에 있다 — 진행자 `SKILL.md`, 전략가·비평가·결재자 `.claude/agents/qld-*.md`. 바뀐 이유와 이력은 `LEDGER.md`.

목표: 상승장에서는 단순 적립(DCA) 수익을 따라가고, 폭락에서는 최악 IRR과 MDD를 줄이는 QLD 적립 규칙. 규칙은 단순할수록 좋다.

## 흐름

한 요청 = 한 스텝 = 서로 다른 전략 방향 3~4개. 계산·기록·커밋은 `lib/step.js`가 하고, LLM은 아이디어(전략가)와 숫자 기준을 통과한 후보의 판단(비평가·결재자)만 한다. 대부분의 스텝이 기각이므로 넓게 보고 숫자로 걸러지지 않은 것만 따진다.

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 0 준비 | 코드 | `step.js prep`: pull, 데이터 새로고침, 다음 스텝 번호, 필요할 때만 넓은 스크린, BRIEF 갱신 |
| 1 전략가 | LLM 1명 | BRIEF만 읽고 방향을 `steps/Sxx-plan.json`에 등록, 모듈 작성, `step.js check`로 오류·발동률·챔피언과 보유 상태가 다른 날 수만 확인(두 지수 모두 0.3% 미만이면 사실상 챔피언이라 값 교체 허용, T11). 점수를 보지 않는다 |
| 2 실행 | 코드 | `step.js run`: 계획·모듈 커밋(사전 등록) → 전 설정 스크린 → 방향별 최고 설정에 배터리 → `steps/Sxx.md` → 게이트 |
| 3 검토 | 조건부 | 게이트가 "검토 필요"일 때만 비평가 → 결재자 |
| 4 마감 | 코드 | `step.js close`: 스텝 문서 결론, LEDGER, IDEAS, BRIEF 갱신, 커밋·푸시 |

게이트: 방향의 최고 설정이 배터리 자동 판정(A1~A5·A7·A10)을 모두 통과하거나 보류 조건에 들면 "검토 필요", 아니면 자동 기각(숫자가 이유를 대신한다).

## 검증 세트 (스텝 중에 바꾸지 않는다. 바꾸려면 그 자체를 T 스텝으로 한다)

- 주 70만원 적립(배터리는 1억 거치도 함께), 세후 원화, 매일 종가 신호 → 다음 거래일 종가 실행.
- 발견 세트: 나스닥100 10년(1999~2016 시작), 나스닥100 5년. 확인 세트: 나스닥100 10년 1986~1998 시작, S&P 2배 10년·5년.
- 스크린 점수 = min(발견 세트 평균, 확인 세트 평균) of (챔피언 대비 Δ중앙 + 0.5·Δ최악, %p) − 사례 5%p 초과 악화 벌점.
- 사례 구간: 2025, 2022, 2020, 2018, 2008, 2000.
- 판정은 나스닥100과 S&P 2배로만 한다(사용자 결정). 해외 지수 도구(`lib/intl.js`, 배터리 `--intl`)는 참고용이다.

## 채택 기준표

모두 통과해야 채택. A1~A5·A7·A10은 `battery.js`가 자동 판정한다.

| # | 기준 |
|---|---|
| A1 | 표본 밖 세트(N10oos, S10, S5) 어느 것도 챔피언보다 IRR 중앙값이 1.0%p 넘게 나쁘지 않고, 최악 IRR이 2%p 넘게 나쁘지 않다. S&P 세트에서 한 번도 발동하지 않으면 "확인 불가"(보류까지만) |
| A2 | 개선: N10·N10oos·N5 중 최악 IRR이 2%p 이상 좋아지거나, N10과 N10oos의 IRR 중앙값이 둘 다 1%p 이상 좋아진다 |
| A3 | 사례 6개 중 챔피언보다 5%p 넘게 나쁜 구간이 없고, 4개 이상은 나쁘지 않다 |
| A4 | 새 파라미터를 각각 ±20%(또는 바로 옆 값)로 바꿔도 A1·A3을 유지하고 점수가 양수다 |
| A5 | 비용 2배와 7월 시작 구간에서도 점수가 양수다 |
| A6 | 방향당 새 자유 파라미터 2개 이하, 근거는 시험 전에 기록, 임계값은 반올림한 값 |
| A7 | 1999년 이후 이탈 40회 이하 |
| A8 | 미래 정보 없음: 신호는 j일 종가까지, 지표별 발표 시차, 실행은 j+1일 |
| A9 | 다중검정: 방향별 시도(스크린+배터리)가 30회를 넘으면 A2의 개선 폭을 두 배로 올린다 |
| A10 | 플라시보: 같은 신호를 시간축으로 무작위 이동한 20개보다 점수가 높은 비율이 95% 이상. 챔피언 대체형(rule "sig")은 `candidates/S09_lib.js` 기반일 때 훅만 이동해 채점하고, 그렇지 않으면 "해당 없음"(보류까지만) |

보조 경고(비평가가 판단): 연도별 기여에서 한 해가 60% 이상 · 이득 상위 2개 연도를 뺀 챔피언 대비 합계가 음수(한두 해 의존) · 결정적 매매 직전 신호의 문턱 여유 0.05 미만 · 최장 시장 밖 기간이 챔피언보다 크게 김.

보류: A2를 통과했지만 A4·A5 중 하나만 애매하거나 A1이 확인 불가일 때만 쓴다. 보류 안은 같은 데이터로 다시 고르지 않는다.

## 과최적화를 피하는 습관

- 좋은 숫자 하나보다 이웃 값들이 고르게 좋은지를 본다. 플라시보보다 확실히 나아야 한다.
- 개선이 2000년이나 2008년, 1987년 한 구간에서만 나오면 의심한다.
- 규칙을 더하는 대신 빼서 같은 성과가 나오면 빼는 쪽을 채택한다.
- 결과가 좋아도 근거 없는 파라미터를 미세 조정한 것이면 기각한다. "효과 없음"도 좋은 결론이다.
- 채택된 챔피언은 채택일 이후 실제 데이터(매일 `data/status.json`)로 계속 추적한다. 이것이 유일한 진짜 표본 밖이다.

## 운영 규칙

- 엔진 수정은 연구 스텝 안에서 하지 않는다. 사용자 승인 아래 T 스텝으로 하고, 기본값이면 챔피언과 결과가 같은지(차이 0) 확인한다. 매매·세금 코드를 고치면 `node lib/test_tax.js`와 `node lib/enginecheck.js`를 통과시킨다.
- 연구 도구는 `qld/data/status.json`과 `alert.md`를 쓰지 않는다(매일 알림의 원본이라서). 데이터 갱신은 `build.py --research`로 연구 시리즈만, 더 오래된 데이터로는 덮지 않는다.
- 위험 비교의 MDD는 시간가중(`mdd`)을 쓴다. 평가액 낙폭(`mddVal`)은 참고로만 표시한다.
- 채택되어도 백테스터 페이지와 매일 알림은 사용자 승인 뒤에만 바꾼다.
