# QLD 전략 연구 프로토콜

한 번의 요청 = 한 스텝. 스텝마다 여러 역할이 후보를 만들고, 서로 공격하고, 독립된 결재자가 정해진 기준으로 채택·보류·기각을 정한다. 결과는 `steps/`에 남기고 `LEDGER.md`를 갱신한 뒤 사용자에게 보고한다. 사용자가 다음 스텝을 요청하면 반복한다.

## 역할

| 역할 | 하는 일 | 지켜야 할 것 |
|---|---|---|
| 기술 분석가 | 가격·변동성·추세·모멘텀·시장 내부 지표로 후보를 만들고 시험 | 사용자가 말한 지표에 갇히지 말고 최소 5개 이상 능동적으로 검토 |
| 매크로 분석가 | 신용·금리·스트레스·고용·달러·원자재 등으로 후보를 만들고 시험 | 지표별 발표 시차를 각각 반영, 위험 방향은 경제적 의미로 먼저 정함 |
| 레드팀 (과최적화 감사) | 후보를 깨뜨리려 시도: 파라미터 ±20%, 비용 2배, 7월 시작 구간, 표본 밖 시장, 시도 횟수 점검, 미래 정보 누수 점검 | 칭찬 금지. 통과한 것만 "통과"로 적는다 |
| 리스크·실행 담당 | 매매 빈도, 세금(양도세 22%, 250만원 공제, 선입선출), 환율, 실행 가능성, 사용자가 실제로 지킬 수 있는지 | 원금이 커졌을 때와 작을 때를 모두 본다 |
| 결재자 | 위 메모를 읽고 아래 채택 기준표로 판정. 직접 후보를 만들지 않는다 | 기준표의 각 줄을 통과/실패로 적고, 하나라도 실패면 채택 불가 |

## 스텝 진행

1. **범위 정하기**: 사용자 요청을 하나의 질문으로 적는다. `LEDGER.md`의 챔피언과 지난 결론을 읽고, 이미 기각된 아이디어를 다시 시험하려면 무엇이 달라졌는지 적는다.
2. **사전 등록** (시험 전에 `steps/Sxx-*.md`에 기록): 후보마다 가설, 경제적·행동적 근거, 새 파라미터와 시험할 값(반올림한 값, 많아야 3~5개), 성공 기준.
3. **1라운드 · 연구**: 기술·매크로 분석가가 병렬로 후보를 시험한다. 모든 실행은 `node lib/score.js`로 하고(자동으로 `trials.jsonl`에 기록), 결과를 메모로 낸다.
4. **2라운드 · 공격**: 레드팀과 리스크 담당이 상위 후보를 공격한다. 기술 분석가는 매크로 후보를, 매크로 분석가는 기술 후보를 비판한다.
5. **3라운드 · 수정**: 지적받은 문제만 고친다. 새 파라미터를 추가하지 않는다. 최대 3라운드.
6. **결재**: 결재자가 기준표로 판정한다. 결과는 채택(새 챔피언), 보류(가능성은 있으나 근거 부족), 기각.
7. **기록**: 스텝 문서 완성, `LEDGER.md` 갱신, 채택이면 `champion.json` 갱신. 커밋하고 푸시한다.
8. **보고**: 사용자에게 짧게 보고하고, 다음 스텝 후보 2~3개를 제안한다. 채택된 전략을 백테스터 페이지와 매일 알림에 반영하는 것은 **사용자가 승인한 뒤에만** 한다.

## 검증 세트 (스텝 사이에 바꾸지 않는다)

- 주 70만원 적립(필요하면 1억 거치도 함께), 세후 원화, 매일 종가 신호 → 다음 거래일 종가 실행.
- 나스닥100 10년 (1999~2016 시작), 나스닥100 10년 1986~1998 시작 (표본 밖), S&P 2배 10년·5년 (표본 밖), 나스닥100 5년.
- 사례 구간: 2025, 2022, 2020, 2018, 2008, 2000.
- 비교 대상: 단순 적립(DCA)과 현재 챔피언. `lib/score.js`가 둘 다 자동으로 계산한다.
- 데이터를 새로 받으면(`python3 research/refresh_data.py`) 챔피언 수치도 다시 계산해 스텝 문서에 데이터 마지막 날짜와 함께 적는다.

## 채택 기준표 (모두 통과해야 채택)

| # | 기준 |
|---|---|
| A1 | 표본 밖 세트(N10oos, S10, S5) 어느 것도 챔피언보다 IRR 중앙값이 1.0%p 넘게 나쁘지 않고, 최악 IRR이 2%p 넘게 나쁘지 않다 |
| A2 | 개선: N10·N10oos·N5 중 최악 IRR이 2%p 이상 좋아지거나, N10과 N10oos의 IRR 중앙값이 둘 다 1%p 이상 좋아진다 (A1 허용 범위 안에서) |
| A3 | 사례 6개 중 챔피언보다 5%p 넘게 나쁜 구간이 없고, 4개 이상은 나쁘지 않다 |
| A4 | 새 파라미터를 각각 ±20%(또는 바로 옆 격자값)로 바꿔도 A1~A3을 유지한다 (봉우리가 아니라 고원) |
| A5 | 비용 2배(`costMult: 2`)와 7월 시작 구간(`startMonth: 7`)에서도 개선 방향이 유지된다 |
| A6 | 스텝당 새 자유 파라미터 2개 이하, 근거는 시험 전에 기록, 임계값은 반올림한 값 |
| A7 | 1999년 이후 이탈 횟수 40회 이하 (연 1.4회 수준) |
| A8 | 미래 정보 없음: 신호는 j일 종가까지, 매크로는 지표별 발표 시차 반영, 실행은 j+1일 |
| A9 | 다중검정: 스텝 시도 횟수를 적는다. 30회를 넘으면 A2의 개선 폭을 두 배(4%p / 2%p)로 올린다 |

보류는 A2는 통과했지만 A4·A5 중 하나가 애매할 때만 쓴다. 보류 안은 다음 스텝에서 같은 데이터로 다시 고르지 않는다(새 근거나 새 데이터가 있어야 함).

## 과최적화를 피하는 습관

- 넓게 촘촘히 훑지 않는다. 사전 등록한 몇 개 값만 본다.
- 좋은 숫자 하나보다 이웃 값들이 고르게 좋은지를 본다.
- 개선이 2000년이나 2008년 한 구간에서만 나오면 의심한다.
- 규칙을 더하는 대신 빼서 같은 성과가 나오면 빼는 쪽을 채택한다.
- 채택된 챔피언은 채택일 이후 실제 데이터(매일 `data/status.json`)로 계속 추적한다. 이것이 유일한 진짜 표본 밖이다.

## 보고 형식 (사용자에게, 한국어, 휴대폰에서 읽기 좋게)

1. 결론 한 줄과 결재 결과(채택·보류·기각)
2. 핵심 수치 표: 챔피언 / 최선 후보 / 단순 적립
3. 토론 요지: 역할마다 한두 줄, 반대 의견 포함
4. 과최적화 점검 결과 (A4·A5·A9)
5. 다음 스텝 후보 2~3개, 채택이면 페이지 반영 여부 질문
