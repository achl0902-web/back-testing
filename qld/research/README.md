# QLD 전략 연구실

> 누가 읽나: 사람. 무엇을 하나: 폴더 안내와 "어떤 규칙이 어디에 있나". 규칙 자체는 여기 없다.

QLD 적립 규칙(현재 챔피언: 기술 4축 + 매크로 이탈 경보)을 스텝 단위로 시험하는 작업 공간이다. 한 스텝은 코드 파이프라인(`lib/step.js`)이 사전 등록·채점·기록을 하고, 에이전트는 아이디어와 판단만 한다.

## 규칙이 있는 곳 (한 규칙은 한 곳에만)

| 무엇 | 파일 |
|---|---|
| 흐름, 검증 세트, 채택 기준표, 과최적화 습관, 운영 규칙 | `PROTOCOL.md` |
| 진행자 절차(준비→전략가→실행→검토→마감→보고) | `SKILL.md` |
| 전략가·비평가·결재자 지시 | `../../.claude/agents/qld-*.md` |
| 계획 형식, 신호 모듈 훅, 엔진 파라미터 설명 | `lib/brief.js`(BRIEF.md로 생성) |
| 현재 챔피언, 스텝별 결론, 사용자 결정 | `LEDGER.md` |
| 시험한 곳과 빈칸, 안 해 본 아이디어 | `IDEAS.md` |

## 파일

| 경로 | 내용 |
|---|---|
| `BRIEF.md` | 전략가가 읽는 유일한 요약(자동 생성, 손으로 고치지 않는다) |
| `champion.json` | 현재 챔피언 설정 |
| `steps/` | 스텝별 사전 등록 계획, 스크린·배터리 결과, 비평·결재, 결론 |
| `candidates/` | 신호 모듈. 챔피언 대체형은 `S09_lib.js` 기반 |
| `trials.jsonl` | 채점할 때마다 쌓이는 시도 기록(다중검정 A9) |
| `lib/step.js` | 스텝 파이프라인: `prep` · `check` · `run` · `close` · `criteria` |
| `lib/score.js` | 표준 점수표(5개 세트 × DCA·챔피언 + 사례 6개). 사용법은 파일 머리 주석 |
| `lib/screen.js`, `lib/battery.js` | 넓은 스크린, 결선 검증과 자동 판정 |
| `lib/catalog.js`, `lib/macro.js` | 지표 카탈로그(발표 시차·z점수), 매크로 원자료 |
| `lib/core.js`, `lib/data.js` | 채점 핵심과 기준선 캐시, 데이터·검증 구간 |
| `lib/test_tax.js`, `lib/enginecheck.js` | 엔진 매매·세금 회귀 검사 |
| `lib/robust.js`, `lib/hist.js`, `lib/compare.js` 등 | T 스텝(챔피언 검증)용 도구 |
| `data/` | 나스닥100(합성 QLD, 매크로 경보)과 S&P 2배 데이터 |
