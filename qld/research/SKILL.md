# QLD 연구 스텝

> 누가 읽나: 진행자(이 세션). 무엇을 하나: 한 스텝을 시작부터 보고까지 진행한다. 필요한 명령은 모두 여기 있으니 다른 문서는 읽지 않는다. 기준과 흐름의 원본은 `PROTOCOL.md`, 역할별 지시는 `.claude/agents/qld-*.md`.

## 진행자 원칙

- 스크립트 출력만 본다. BRIEF·IDEAS·PROTOCOL·엔진·스텝 문서를 읽지 않고, 문서를 손으로 쓰지 않고, 엔진을 고치거나 격자를 짜지 않는다. 진행자가 읽으면 그 내용이 매 턴 다시 읽혀 토큰이 커진다.
- 메시지는 시작 한 줄과 최종 보고뿐이다. 작업 목록 위젯은 쓰지 않는다. 사용자에게는 한국어로 쓴다.
- 새 세션에서 저장소 루트로 시작한다. 그래야 경량 에이전트 정의가 로드된다(범용 에이전트는 호출당 약 5만 토큰).
- 에이전트를 재개(SendMessage)해 토론시키지 않는다. 결과를 본 뒤 같은 스텝의 계획을 고쳐 다시 run하지 않는다(계획 오류 수정은 예외).
- 비밀값(FRED 키 등)을 출력하거나 커밋하지 않는다.
- 목표: 자동 기각 스텝 약 15만, 검토 스텝 약 22만 토큰.

## 1. 준비

1. 저장소가 없으면 `add_repo`(push) 후 `git clone --depth 1 https://github.com/achl0902-web/back-testing /home/claude/back-testing`(timeout 10분). 있으면 그대로 둔다(prep이 pull한다).
2. `cd /home/claude/back-testing/qld/research && node lib/step.js prep`(timeout 15분). 출력의 스텝 번호 `Sxx`를 쓴다.
3. 사용자에게 한 문장으로 시작을 알린다.

## 2. 전략가 (에이전트 1명)

`qld-strategist`를 띄운다. 목록에 없으면 general-purpose에 "먼저 /home/claude/back-testing/.claude/agents/qld-strategist.md를 읽고 그 지시를 그대로 따르라"를 붙인다. 프롬프트는 5줄 이내: 스텝 번호, 사용자 아이디어(있으면 방향 하나로), 사용자 제약.

## 3. 실행 (코드)

`node lib/step.js run Sxx`(timeout 30분). 사전 등록 커밋, 스크린, 배터리, 스텝 문서, 게이트까지 한다.
- 계획 오류가 나오면 메시지대로 plan의 해당 칸만 고치고 다시 run한다.
- 한 방향이 "결과 없음(오류)"이면 그대로 두고 보고에 적는다.

## 4. 검토 (게이트가 "검토 필요"일 때만)

1. 비평가 `qld-critic`(없으면 같은 방식으로 정의 파일을 읽게 한다). 프롬프트: 스텝 번호, 검토할 방향 id, run 출력 전문, `node lib/step.js criteria` 출력.
2. 결재자 `qld-judge`. 프롬프트: run 출력, 비평 메모, `node lib/step.js criteria` 출력.

## 5. 마감 (코드)

```
node lib/step.js close Sxx --verdict "<방향별 판정 한 줄>" --why "<핵심 근거 한 줄>" --ideas '[{"row":"<IDEAS 행동 유형 행>","tested":"<이번 시험 요약>","result":"<결론>","gap":"<남은 빈칸>"}]' --session <세션 URL>
```

채택이면 close 전에 `champion.json`과 LEDGER 챔피언 절을 고친다. 페이지와 매일 알림은 사용자 승인 뒤에만 바꾼다(승인되면: engine·page·build 수정 → 로컬 빌드와 playwright 렌더 확인 → 푸시 → Actions 성공 확인).

## 6. 보고 (휴대폰에서 읽기 좋게)

1. 결론 한 줄(방향별 판정)
2. 방향 표(유형 · 내용 · 최고 점수 · 판정)
3. 검토 요지와 반대 의견(검토가 있었을 때만)
4. 과최적화 점검(게이트 줄 기준)
5. 다음 스텝 후보 2~3개
6. 채택이면 "백테스터와 매일 알림에 반영할까요?"

사용자가 요청하면 토큰 사용량(에이전트별 + 메인 추정)과 구조 진단을 붙인다.

## 규칙을 고칠 때

사용자가 규칙을 바꾸거나 판단이 틀렸다고 하면, 그 규칙이 사는 파일의 문장을 다시 쓴다(덧붙이지 않는다). 기준·흐름·검증 세트는 `PROTOCOL.md`, 진행자 절차는 이 파일, 역할별 지시는 에이전트 정의, 바뀐 이유는 LEDGER의 해당 스텝 행이나 D 행에 남긴다. 코드로 막을 수 있으면 `step.js` 검사로 옮긴다.
