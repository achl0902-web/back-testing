# QLD 연구 스텝 v3

규칙 원본은 저장소 `qld/research/PROTOCOL.md`(v3)다. 진행자가 그 문서를 읽지 않아도 되도록, 필요한 명령은 이 스킬에 다 적었다. 사용자에게 보내는 모든 메시지는 한국어로 쓴다.

**진행자(이 세션)는 다음을 하지 않는다.**
- BRIEF·IDEAS·PROTOCOL·엔진·스텝 문서를 읽지 않는다.
- 엔진을 고치거나 격자를 설계하지 않는다.
- 문서를 손으로 쓰지 않는다.
- 작업 목록 위젯과 중간 진행 메시지를 쓰지 않는다. 메시지는 시작 한 줄과 최종 보고뿐이다.

각 단계에서는 스크립트 출력만 본다.

## 1. 준비

1. 저장소 `achl0902-web/back-testing`을 준비한다.
   - 없으면 add_repo(push) 후 `git clone --depth 1 https://github.com/achl0902-web/back-testing /home/claude/back-testing`을 실행한다(timeout 10분).
   - 있으면 그대로 둔다. prep이 pull한다.
2. `cd /home/claude/back-testing/qld/research && node lib/step.js prep`을 실행한다(timeout 15분).
3. 출력에 나온 스텝 번호 `Sxx`를 쓴다.
4. 사용자에게 한 문장으로 시작을 알린다.

## 2. 전략가 (에이전트 1명)

- `qld-strategist`가 에이전트 목록에 있으면 그것을 쓴다.
- 없으면 general-purpose에 다음 문장을 붙인다: "먼저 /home/claude/back-testing/.claude/agents/qld-strategist.md를 읽고 그 지시를 그대로 따르라".
- 프롬프트는 5줄 이내로 쓴다. 넣을 것:
  - 스텝 번호
  - 사용자 아이디어(있으면 방향 하나로)
  - 사용자 제약(예: 검증은 나스닥100·S&P 2배까지)
- 전략가는 `steps/Sxx-plan.json`과 모듈을 만들고, `step.js check`까지만 한다. 점수는 보지 않는다.

## 3. 실행 (코드, 토큰 0)

1. `node lib/step.js run Sxx`를 실행한다(timeout 30분).
   - 계획과 모듈을 먼저 커밋한다(사전 등록).
   - 전 설정을 스크린하고, 방향별 최고 설정에 배터리를 돌린다.
   - `steps/Sxx.md`를 작성하고, 20줄 이내 요약과 게이트를 출력한다.
2. 계획 오류가 나오면 메시지대로 plan의 해당 칸만 고치고 다시 run한다.
3. 한 방향이 "결과 없음(오류)"이면 그대로 두고 보고에 적는다.

## 4. 검토 (게이트가 "검토 필요"일 때만)

"자동 기각"이면 이 단계를 건너뛴다.

1. **비평가** `qld-critic`(없으면 general-purpose에 같은 방식으로 정의 파일을 읽게 한다)
   - 프롬프트: 스텝 번호, 검토할 방향 id, run 출력 전문
   - 비평가는 배터리·계획·모듈 파일을 직접 읽는다.
2. **결재자** `qld-judge`(도구 없음)
   - 프롬프트에 run 출력, 비평 메모, 아래 기준 요약을 붙인다.
   - 기준 요약:
     - A1 표본 밖 중앙 −1·최악 −2%p 이내 (S&P에서 발동이 없으면 확인 불가)
     - A2 최악 +2%p, 또는 N10·N10oos 중앙 둘 다 +1%p (방향별 시도 30회 초과 시 기준 2배)
     - A3 사례 중 −5%p 초과 악화 없음, 4개 이상 비악화
     - A4 이웃값 유지
     - A5 비용 2배·7월 시작 양수
     - A6 파라미터 2개 이하, 사전 근거
     - A7 이탈 40회 이하
     - A8 미래 정보 없음
     - A10 플라시보 95%
     - 보류: A2 통과 + (A4·A5 중 하나만 애매, 또는 A1 확인 불가)

## 5. 마감 (코드)

다음을 실행한다:
`node lib/step.js close Sxx --verdict "<방향별 판정 한 줄>" --why "<핵심 근거 한 줄>" --ideas '[{"row":"<IDEAS 행동 유형 행>","tested":"<이번 시험 요약>","result":"<결론>","gap":"<남은 빈칸>"}]' --session <세션 URL>`

- 스텝 문서 결론, LEDGER, IDEAS(시험한 것은 덧붙이고, 결론·빈칸은 교체), BRIEF를 갱신하고 커밋·푸시한다.
- 채택이면 close 전에 `champion.json`과 LEDGER 챔피언 절을 고친다.
- 페이지와 매일 알림은 사용자 승인 뒤에만 바꾼다.

## 6. 보고 (휴대폰에서 읽기 좋게 짧게)

1. 결론 한 줄(방향별 판정)
2. 방향 표(유형 · 내용 · 최고 점수 · 판정)
3. 검토 요지와 반대 의견(검토가 있었을 때만)
4. 과최적화 점검(게이트 줄 기준)
5. 다음 스텝 후보 2~3개
6. 채택이면 "백테스터와 매일 알림에 반영할까요?"

사용자가 요청하면 토큰 사용량(에이전트별 사용량 + 메인 추정)과 구조 진단을 붙인다.

## 페이지 반영 (승인 후)

engine/page/build를 수정한다 → 로컬 빌드와 playwright 렌더를 확인한다 → 푸시한다 → Actions 성공을 확인한다.

## 금지

- 에이전트 재개(SendMessage) 토론
- 해외 지수로 판정하기
- 비밀값(FRED 키 등)을 출력하거나 커밋하기
- 결과를 본 뒤 같은 스텝에서 계획을 고쳐 다시 run하기. 계획 오류 수정은 예외다.
